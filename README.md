دردشة خاصة — النسخة الأمنية 2.0
المتطلبات
Node.js 20 أو أحدث.
تشغيل npm install لتنزيل المكتبات.
تشغيل محلي
npm install
npm start
افتح http://localhost:3000.

كيف تعمل الغرف؟
ينشئ المستخدم غرفة من الواجهة، ويولد الخادم رمز دعوة عشوائياً باستخدام crypto.randomBytes (144 بت من العشوائية).
يشارك صاحب الغرفة الرمز مع الشخص الآخر. على الشخص الآخر فتح الموقع واختيار «لديّ رمز دعوة».
الرموز والغرف مؤقتة داخل ذاكرة الخادم، وتحذف الغرف الخالية بعد 30 دقيقة؛ إعادة تشغيل الخادم تنهي الغرف.
لا توجد قاعدة بيانات للرسائل، ولا سجل دائم.
يتم إنشاء مجلد data تلقائياً لتخزين جلسات SQLite.

إعدادات الإنتاج
اضبط متغير بيئة NODE_ENV=production وSESSION_SECRET عشوائياً بطول 32 حرفاً أو أكثر. مثال توليد قيمة:

node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
استخدم استضافة Node.js تدعم WebSockets وHTTPS. فعّل HTTPS/WSS، واضبط trust proxy فقط إذا كانت المنصة خلف وكيل موثوق واحد. اختبر إعدادات الكوكيز خلف منصة الاستضافة.

ميزات الحماية
رموز دعوة قوية عشوائية وليست أسماء غرف قصيرة.
يتحقق الخادم من وجود الغرفة وصلاحية الرمز قبل الانضمام.
كل رسالة تتحقق من عضوية socket في الغرفة الفعلية على الخادم (socket.rooms.has(room))، ولا يعتمد الخادم على رمز الرسالة وحده.
حد معدل للأحداث لكل اتصال: الرسائل 8 خلال ثانيتين، والانضمام 5 في الدقيقة، والكتابة 4 خلال ثانيتين.
حد معدل لطلبات HTTP، وحد أقصى لطول الرسالة والاسم وحجم حزمة Socket.IO.
جلسات HTTP محفوظة في SQLite، وكوكي HttpOnly وSameSite=Strict وSecure في الإنتاج.
Helmet ورؤوس أمان أساسية.
حدود وملاحظات أمنية
حد الأحداث المطبق في الذاكرة لكل socket لا يعمل كمحدد موزع عبر عدة نسخ خادم، ويمكن تجاوزه بإنشاء اتصالات كثيرة. في النشر الكبير استخدم Redis adapter ومحدد معدل موزعاً وقيود اتصال على مستوى الوكيل.
رمز الدعوة بمنزلة سرّ حامل: أي شخص يحصل عليه يستطيع الانضمام. لا تنشره علناً، وشارك الرابط/الرمز عبر قناة موثوقة.
لا يوجد تشفير طرفي؛ TLS يحمي النقل بين المتصفح والخادم فقط، وليس من الخادم نفسه.
الجلسات تستخدم SQLite. مجلد data يُنشأ تلقائياً عند التشغيل؛ تأكد أن الاستضافة تسمح بالكتابة المستمرة إذا أردت بقاء الجلسات. على استضافات الملفات المؤقتة، استخدم مخزن جلسات خارجي مثل Redis.
إدارة الغرف/رموزها في الذاكرة مؤقتة، لذلك يلزم إعادة إنشاء الغرف بعد إعادة تشغيل الخادم.
لا تستخدم هذه النسخة لمعلومات عالية الحساسية قبل مراجعة أمنية واختبارات تحميل واختبارات مصادقة مستقلة.
تعديلات النسخة 2.1
نقل سكربت الصفحة إلى public/app.js: سياسة CSP كانت تمنع السكربت المضمّن فلا تعمل الواجهة.
إعادة تحميل الجلسة عند join، فيعمل الدخول إلى غرفة ثانية بعد المغادرة دون إعادة تحميل الصفحة.
إعادة انضمام تلقائية للغرفة بعد انقطاع الاتصال.
تخزين هاش SHA-256 للرمز (وليس الرمز نفسه) في الجلسة وذاكرة الخادم.
حذف الاعتماديتين غير المستخدمتين connect-redis وioredis.
تعديلات النسخة 2.2
حد لعدد أعضاء الغرفة (MAX_ROOM_MEMBERS، الافتراضي 10) وحد لعدد الغرف (MAX_ROOMS).
عدد المتصلين يتحدّث للجميع عند أي دخول أو خروج.
حدّان إضافيان لطلبات إنشاء الغرف والانضمام لكل عنوان IP.
إذا تعذّر تحميل connect-sqlite3 يعمل الخادم بمخزن جلسات مؤقت بدل أن ينهار.
إيقاف upgrade-insecure-requests في التطوير المحلي (يفيد Safari)، وتفعيله في الإنتاج.
إخفاء مؤشر "يكتب الآن" عند مغادرة الشخص، وعدم تكرار إشعار الانضمام عند إعادة الاتصال.
إغلاق نظيف عند إيقاف الخادم، وإضافة .env.example و.gitignore.
ملاحظة: بعد انقطاع الشبكة يبقى الاتصال القديم محسوباً حتى ينتهي ping (حوالي 45 ثانية)، فلا تضبط الحد على قيمة ضيقة جداً.
